# Pinecone 部署步骤（接收方操作指南 · 联网版）

> 本包包含 **backend / frontend 2 个应用镜像** + 配置文件。
> **前提：目标机可访问 Docker Hub**（postgres / redis 由 compose 在启动时自动拉取，无需手动下载）。

---

## 一、包内容清单

| 文件 | 说明 |
|---|---|
| `pinecone-backend.tar` | API 服务镜像（NestJS） |
| `pinecone-frontend.tar` | 前端镜像（Next.js） |
| `config/docker-compose.prod.yml` | 编排文件（backend/frontend 镜像名已固定；postgres/redis 自动拉取） |
| `config/docker/postgres/init-v2/01-init.sh` | 建库建用户脚本 |
| `config/docker/postgres/init/02-schema.sql` | 建表 SQL |
| `config/.env.prod.example` | 环境变量模板（复制为 .env.prod 填值） |

> 💡 postgres（18.4）和 redis（7-alpine）是 Docker Hub 官方公开镜像，**无需随包分发**——`docker compose up -d` 首次启动时自动下载。仅离线内网环境才需另备这两个镜像。

---

## 二、前置要求

- 目标机已装 **Docker**（≥24）+ **Docker Compose**（v2 内置）
- **目标机可访问 Docker Hub**（拉取 postgres/redis 官方镜像）
- 磁盘 ≥ 2GB 空闲；端口 **3000 / 6173** 空闲

---

## 三、部署步骤（3 步）

### Step 1：导入镜像（2 个 tar）

```bash
# 在包目录下执行
docker load < pinecone-backend.tar
docker load < pinecone-frontend.tar
```

验证：`docker images` 应能看到 `pinecone-backend:latest` / `pinecone-frontend:latest`。

### Step 2：准备配置

```bash
# 进入 config 目录，复制 env 模板
cd config
cp .env.prod.example .env.prod

# 编辑 .env.prod，至少修改以下项：
# ① DB_PASSWORD / APP_DB_PASSWORD：改成自己的强密码（≥16 位）
# ② JWT_ACCESS_SECRET / JWT_REFRESH_SECRET：改成自己的随机串（≥32 位）
# ③ FRONTEND_URL / API_URL / WS_URL：改成目标机实际访问地址
#    - 本机单机部署可保持 http://localhost:6173 / http://localhost:3000/api
#    - 服务器部署改成 http://<服务器IP>:6173 等
# ④ REGISTRATION_ADMIN_EMAILS：填管理员邮箱
```

> ⚠️ **重要**：如果改了 API_URL / WS_URL（非 localhost），frontend 镜像里的地址是**构建时写死的**，需要重新构建 frontend 镜像（见第五节）。本机部署保持 localhost 则无需重建。

### Step 3：启动全栈

```bash
# 在 config 目录下执行（docker-compose.prod.yml 引用 ./docker/postgres 相对路径，保持目录结构）
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d
```

首次启动会自动：
1. **从 Docker Hub 拉取 postgres:18.4 和 redis:7-alpine**（目标机需联网）
2. postgres 容器首次启动执行 init 脚本：建库 → 建用户 → 建表

> ✅ **镜像名已固定在 compose 中**：backend = `pinecone-backend:latest`、frontend = `pinecone-frontend:latest`，与 Step 1 `docker load` 的 tar 完全一致。无论把包解压到哪个目录（目录名任意，如 `config` / `deploy`），compose 都会按固定镜像名匹配已 load 的镜像。
> ⚠️ **不要加 `--build`**：本包不含源码，`up -d --build` 会尝试在目标机重新构建（找不到 Dockerfile / 源码）而失败。正确命令就是上面的 `up -d`。

## 四、验证

```bash
# 后端健康检查（应返回 200）
curl http://localhost:3000/api/health

# 查看容器状态（应 4 个全 Up，postgres 为 healthy）
docker compose -f config/docker-compose.prod.yml ps

# 浏览器访问前端
# 本机：http://localhost:6173
# 服务器：http://<服务器IP>:6173
```

## 五、常见问题

| 问题 | 解决 |
|---|---|
| 启动时提示拉取 postgres/redis 失败 | 目标机无法访问 Docker Hub：① 检查网络/镜像加速器配置 ② 离线环境需另备 postgres:18.4 / redis:7-alpine 镜像 tar 并 `docker load` |
| 加了 `--build` 报「找不到 Dockerfile / 构建失败」 | 本包不含源码，backend/frontend 镜像名已固定在 compose，load tar 后直接 `up -d`，不要加 `--build` |
| 改了 API_URL/WS_URL 但前端连不上后端 | 前端镜像地址构建时写死，需重建：`docker compose -f docker-compose.prod.yml --env-file .env.prod build frontend` 后 `up -d` |
| postgres 容器启动失败（卷挂载错误） | 本包 compose 已用 postgres 18.4 新路径 `/var/lib/postgresql`，无需处理；若用旧版 compose 报 unused mount，改卷路径 |
| 端口 3000/6173 被占用 | `netstat -ano | findstr 3000` 查占用进程，释放后重试 |
| 忘记 .env.prod | compose 会用缺省值，但生产建议显式配置（尤其 REGISTRATION_MODE=whitelist 防开放注册） |

## 六、回滚 / 停止

```bash
# 停止并删除容器（保留数据卷）
docker compose -f config/docker-compose.prod.yml down

# 连数据卷一起删（⚠️ 数据丢失，谨慎）
docker compose -f config/docker-compose.prod.yml down -v

# 删除镜像（如需回退版本）
docker rmi pinecone-backend:latest pinecone-frontend:latest
```
